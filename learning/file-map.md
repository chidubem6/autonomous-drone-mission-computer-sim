- src/drone.c — known (2026-09-15) — the engine itself: holds one DroneState, advances it one time-slice at a time with tick(), loops forever in main() at 20 Hz, and renders each state as one telemetry line → [[pointers]], [[printf-format]], [[simulation-tick]], [[delta-time]], [[named-constants]], [[main-loop]], [[sleep-and-timing]], [[fixed-timestep]], [[battery-model]], [[clamping]], [[conditionals]], [[implicit-state]], [[arrays-of-structs]], [[waypoint-list]], [[for-loop]], [[array-length-is-not-stored]], [[vectors-and-distance]], [[address-of-array-element]], [[heading-and-direction]], [[atan2-and-quadrants]], [[angle-normalisation]], [[bearing-vs-heading]], [[trig-components]], [[passing-dependencies-as-parameters]]; since 2026-09-16 it also holds the mission — an array of three Waypoints announced at startup — plus distance_to() and bearing_to(), which report how far and which way to the current waypoint every tick; since 2026-09-17 tick() also takes the target waypoint, so the drone steers onto the bearing, moves along it at cruise speed, and climbs to that waypoint's own altitude; since 2026-09-20 it also flies the mission to its end — an arrival radius decides when a waypoint counts as reached, current_wp advances, each arrival is announced, and the loop breaks with MISSION COMPLETE rather than indexing past the array → [[arrival-threshold]], [[loop-control-break]], [[off-by-one-errors]], [[undefined-behaviour]], [[truthiness-in-c]]; since 2026-09-20 the mission runs as an explicit state machine — tick() only moves the drone horizontally in MODE_NAVIGATE, a transition rule at the end of tick() flips TAKEOFF to NAVIGATE once the climb reaches the target altitude, and the main loop runs `while (drone.mode != MODE_COMPLETE)` instead of escaping with break → [[finite-state-machine]], [[enums]], [[zero-initialization]], [[code-smell]]; since 2026-09-21 it is the ENGINE ONLY — main() moved out to src/main.c, and with it the mission, the loop, the sleeping and the constants that were decisions rather than physics (TICK_S, ARRIVAL_RADIUS_M, MISSION_WAYPOINT_COUNT). What is left is capabilities: given a drone and a slice of time, advance it; given a drone and a waypoint, measure it. It decides nothing, has no main(), and is compiled into both programs → [[engine-vs-program-separation]], [[interface-vs-implementation]], [[compilation-stages]]
- src/drone.h — known (2026-09-16) — the shapes the engine is built from: DroneState (where the drone IS) and Waypoint (where it is MEANT to go), shared with every file that needs them; since 2026-09-20 it also declares FlightMode, the three-value enum naming what the drone is doing, and DroneState carries a `mode` field of that type ; since 2026-09-21 it also declares the engine's four functions — tick, distance_to, bearing_to, print_state — making it the engine's public interface: the only thing main.c and the test ever read about drone.c, since the compiler can never look at another .c file → [[struct]], [[include-guards]], [[comments-that-lie]], [[enums]], [[finite-state-machine]], [[declaration-vs-definition]], [[interface-vs-implementation]], [[header-files]]
- src/main.c — known (2026-09-21) — the mission program: the decisions. Owns this specific drone, this specific three-waypoint mission, the choice to tick at 20 Hz, the sleeping that makes it real-time, and the stopping condition. Every one of those is a choice, and none is a fact about drones — which is why they are here and not in the engine → [[engine-vs-program-separation]], [[main-loop]], [[arrays-of-structs]], [[waypoint-list]]
- tests/ — known (2026-09-21) — the test programs: code that makes claims about the engine and checks them. One file for now; it splits by aspect the day running a subset actually saves time → [[test-program]]
- tests/test_drone.c — known (2026-09-22) — claims about the engine, written as asserts. Links the REAL engine, never a copy, so it cannot go stale behind a bugfix. Claim 1: after a tick, the battery is lower than it was. Claim 2 (2026-09-22): flying east at 10 m/s for one second lands the drone at x = 10, and leaves y alone — set up as its OWN drone and waypoint rather than reusing claim 1's, with the waypoint deliberately far past the answer so no engine can pass by snapping to the target. Both claims compare with fabs(actual - expected) < TOLERANCE_M rather than ==, because binary rounding put 6.1e-16 m of phantom drift into y. Every claim here has been proved fair by breaking the engine and watching it abort. Since 2026-09-24 each claim is its own function named after what it claims, so a failure prints the claim's name instead of `main:`, names like `d` and `w` can be reused, and nothing in main() is visible to any claim. Claims 3-8 test the engine at its forks: a dead drone (battery exactly 0) sinks; a healthy drone climbs toward a higher target, descends toward a lower one, and holds exactly at its target; and inside one step of the target the climb and descent caps land it exactly (checked with ==, because exactness is the claim), with the takeoff→navigate transition asserted at that same pivot → [[assert]], [[test-program]], [[compile-time-vs-run-time]], [[test-fairness]], [[test-isolation]], [[nan-and-float-comparison]], [[choosing-a-tolerance]], [[named-constants]], [[edge-cases]], [[variable-scope]], [[tests-check-behaviour-not-code]]
